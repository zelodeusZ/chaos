# Development Roadmap — Chaos

This roadmap is a planning scaffold, not a claim that any stage is complete. The owner sets priorities.

## Stage 0 — Establish a trustworthy baseline
- [ ] Inspect the target Roblox experience, Untitled Experience.
- [ ] Confirm the active place is not the reference-only Example.
- [ ] Inventory relevant services, folders, scripts, modules, remotes, data stores, and UI.
- [ ] Map each major feature to its actual source location.
- [ ] Record what is implemented, incomplete, broken, and not started.
- [ ] Record reproducible test procedures and known regressions.

## Stage 1 — Consolidate project design
- [ ] Review existing race and Race Trait design.
- [ ] Review seven globally unique Chaos Emeralds and stat mapping.
- [ ] Review Chaos Energy, Chaos Capacitor, and Control Gloves.
- [ ] Capture remaining owner-approved systems and unresolved questions.
- [ ] Resolve contradictions before implementation.

## Stage 2 — Plan implementation in small verified increments
- [ ] Break owner-approved features into isolated tasks.
- [ ] Identify dependencies and affected scripts before editing.
- [ ] Define acceptance criteria and regression checks for each task.
- [ ] Implement one bounded task at a time.
- [ ] Verify changes in the target experience.

## Stage 3 — Maintain a reliable release baseline
- [ ] Keep architecture and implementation status current.
- [ ] Maintain a test history and known-issues list.
- [ ] Record notable changes and rollback information.
- [ ] Prepare a concise handoff for each new assistant session.

## Prioritization rule
Do not start a roadmap item simply because it is unchecked. Follow CURRENT_TASK.md and the owner's latest explicit instruction.
